# Known limitations and v0.2

- macOS native dialogs, playback/codecs, launch environment, app bundling, and signing/notarization require verification on a real Mac. Linux server-mode checks do not establish that GUI behavior. The native Linux build is driven automatically under Xvfb with openbox, which covers the frameless windows and their drawn controls but not a real desktop environment (GNOME/KDE, Wayland, HiDPI), media playback, or native dialogs. Windows is compiled and unit-tested in CI but its GUI has not been run. Frameless GTK windows carry no window title (Wails skips it), so Linux task switchers show only the application name. WebKitGTK aborts the whole application when its bubblewrap sandbox cannot start; CI lifts the AppArmor user-namespace restriction for that reason, and whether stock Ubuntu 24.04 desktops allow it for this binary has not been checked.
- This environment has no provider credentials and no allowed provider/YouTube destinations; even the providers' documentation sites were unreachable. Live transcription with any provider was not performed. Live discovery and video/audio download were run once against one public YouTube video from WSL (see verification); other sites were not tried. Each provider's requests and responses are tested against local HTTP fixtures written from its published API as remembered, not against the live service, so field names, model names (notably ElevenLabs `scribe_v2`, Deepgram's Chinese support in `nova-3`, AssemblyAI's model names) and Tencent's signature need a live check. The demo uses mock segments. Endpoint/model availability, billing, provider transcription quality, and video availability remain external dependencies.
- Volcengine (Doubao) and iFlytek are not included: Volcengine's single-request API does not take AAC/M4A and its diarization option for that API could not be confirmed, and iFlytek's result format could not be verified. Google Cloud and Azure need service accounts or regional resources and are left out for now. OpenAI-compatible services without diarization (such as SiliconFlow's SenseVoice) work through the custom provider, with speakers left unknown.
- The UI/examples preserve Traditional Chinese and support Chinese transcription. `language=zh` cannot force Traditional Chinese or Taiwanese orthography. No prompt is sent to the diarization model; no automatic script conversion or stylistic rewriting is applied. The user dictionary likewise does not convert Simplified↔Traditional; store Taiwan/Traditional spellings as accepted variants when needed. Wrong spellings shorter than two characters are refused. CSV import/export, shortcut autocomplete, and speaker↔person linking are not in v1.
- Whole transcription segments cannot be reliably split into words for several SRT cues. Boundary-crossing suggestions therefore need manual review. A multi-speaker cue retains multiple annotations; it is not automatically split into new cues. Words selected in the viewer can be moved to their own line within the cue and given a speaker by hand (⌃⌥1–9), and a line's speakers are not shown separately on the timeline (the speakers track shows the cue's combined speakers). Nearby subtitle wording remains visible for human context; v0.1 does not make an extra text-correction model call using that context.
- Different requests do not recognize the same person automatically. Users can rename/map speakers manually; known-speaker voice references are left behind a provider extension boundary.
- SRT import supports UTF-8 (including BOM), standard numeric cue identifiers, multiline text, and comma/dot millisecond timestamps. Legacy encodings, ASS styling, SRT positioning extensions, and direct local VTT editing are not supported. Use yt-dlp/FFmpeg conversion for supported remote VTT tracks.
- The timeline waveform needs FFmpeg and decodes the whole file once per media import; very long files take a while to appear and are held in memory as 50 peaks per second. The waveform is display-only: cue times are edited in the inspector, not by dragging blocks.
- Playback depends on native WebView codecs. Remux/transcode unsupported media separately. Editing is still available when media cannot play.
- Projects retain local absolute media paths and up to 100 undo snapshots. There is no autosave or external-file watcher; save before replacing a project or exiting. Native window-close warnings may vary by WebView. Every save/export requires a new filename.
- yt-dlp downloads may require current JavaScript/EJS dependencies. Restricted/private videos, browser cookies, logins, full episodes, playlists, channels, local speech models, accounts, and cloud synchronization are excluded. No external CLI binaries are bundled.
- The official template's icons are retained; signing identities and installer branding are not release-ready. The native Mac template uses ad-hoc signing, but release signing/notarization is not configured.

Suggested v0.2: delta-based history/autosave, non-destructive project updates with original-file protection, dragging cue edges on the timeline and subtitle splitting, compact word-boundary alignment, tested Traditional Chinese orthography assistance, user-controlled known-speaker references, secure OS keychain configuration, native codec/platform testing, accessible keyboard navigation, and signed/notarized installers.
