# Architecture

The application follows the official Wails v3 React template: `main.go` embeds Vite assets and registers `EditorService`; generated interfaces and callable bindings live under `frontend/bindings`. The backend owns file dialogs, project state, credentials, external commands, and uploads. There is no database, authentication system, or cloud storage.

- `internal/subtitle`: strict UTF-8 SRT cue/timestamp parsing, validation, and export. Imported identifier numbers remain strings; internal cue IDs are separate so duplicate SRT identifiers do not collapse rows.
- `internal/project`: immutable imported cues plus editable state; bounded snapshot-based undo/redo survives JSON reopening. Speaker metadata stays separate from SRT text. Accepting/rejecting a proposal is itself a history operation. Suggestions carry a `source` (`audio` or `dictionary`); replacing analysis results only drops pending suggestions of the same source so both can coexist. Accepting a dictionary suggestion changes only cue text (speakers and review stay as they were). Splitting a cue (at a time and a text offset in code points) and merging it with the next are history operations too; both renumber SRT identifiers sequentially, and a merge moves the second cue's suggestions to the merged cue, where their stale original text keeps them from being accepted.
- `internal/analysis`: transcription provider interface, a registry of providers (OpenAI, Deepgram, AssemblyAI, ElevenLabs, Alibaba Cloud DashScope, Tencent Cloud ASR, and custom OpenAI-compatible endpoints) and their HTTP clients. Asynchronous providers are polled under the analysis context, so cancelling stops them. Provider error bodies are never echoed; only a status code or a short provider error code is shown. Providers under mainland Chinese law and custom endpoints are flagged so the UI can warn before adding them and before uploading. Range-relative timestamps are translated to media timestamps. Alignment uses positive temporal intersections and retains all overlapping speakers; cross-boundary segments are marked for review rather than split into invented words. Correction suggestions are the actual audio transcript, with no extra stylistic rewrite call. Audio suggestions are tagged `source=audio`.
- `internal/dictionary`: a global user glossary in `Mousqueau/dictionary.json` (no database). Entries have a canonical form, accepted variants, wrong spellings (≥2 code points), optional nickname→person link, and notes. Matching claims correct forms first so misspellings cannot fire inside them; checks produce undoable `source=dictionary` suggestions. Damaged files load read-only and refuse overwrite. JSON import previews add/merge/conflict before applying.
- `internal/media`: FFmpeg extraction, local waveform peaks (decoded audio is streamed through memory, never written or uploaded), dependency checks, exclusive output creation, and optional yt-dlp integration. Commands use argument arrays, never shell concatenation. YouTube URLs are normalized to single video IDs, user yt-dlp configuration is ignored, and playlists are rejected.
- `service.go`: serializes state updates with a mutex, returns detached snapshots, rejects edits during long processing, and shares a cancellable context across subprocesses and HTTP. Temporaries are removed. Waveform decoding runs outside that busy state with its own context: a newer request cancels an older one, and shutdown cancels both. Audio is exposed to the player through an HTTP Range-capable route that serves only the selected local file, with no arbitrary path parameter.
- `frontend/src`: an editor-style window (toolbar, cue grid, viewer, tabbed inspector including a dictionary tab, canvas waveform timeline that renders only the visible range, with a scrollbar whose thumb ends zoom, status bar; the cue grid likewise renders only the rows in view), selection/playback synchronization, explicit field application, character-level Traditional Chinese diff highlights, individual suggestion decisions, speaker identity management, dictionary highlighting/filtering, and theme selection. The same bundle also renders the settings, welcome, and dictionary windows, chosen by a `?window=` query. Outside macOS, Go opens every window frameless and adds `chrome=custom` to its URL; the frontend then draws minimise/maximise/close buttons at the right of the title bar (`WindowControls.tsx`) through the Wails window runtime, where the macOS inset title bar leaves room for the traffic lights on the left. Credentials cross the frontend boundary in one direction only: typed into those windows and handed to Go for the credential store, one item per provider (a two-part Tencent credential is stored joined by a colon). Go returns just their source (`env`, `keychain` or none). `settings.json` lists the added providers, their model and custom URL, and the one in use.

Labels from different diarization requests are namespaced per run because OpenAI's “A” is not a persistent identity. Users can rename identities and manually assign cues to a shared identity. This avoids falsely identifying people across requests. A future provider can add voice-reference support without conflating original cues, edited cues, segments, identities, and suggestions.

A complete snapshot per operation is intentionally simple for v0.1. With 100 history entries this is suited to moderate subtitle files; long episodes should use a compact command/delta history later. Persistence uses new files rather than in-place writes to protect source material. Explicit approval before upload is part of the editor flow, independently of authorization to download audio.
- `internal/settings`, `internal/keychain`, `internal/update`: preferences as one atomically replaced JSON file, the OpenAI key in the system credential store (macOS keychain through `/usr/bin/security` and Linux Secret Service through `secret-tool`, the key passed on stdin and never as an argument; Windows Credential Manager through the `advapi32` credential API), and a read-only GitHub release lookup with semantic-version ordering. `internal/media` resolves FFmpeg and yt-dlp from a configured location, `PATH`, or (outside Windows) the Homebrew folders and `/usr/local/bin`. None of them depend on Wails; `settings_service.go` exposes them and owns the three windows and the macOS menu; Windows and Linux have no native application menu; a three-line button to the left of the editor project title opens a frontend menu for file operations, undo/redo, settings and window controls. Its actions share the toolbar handlers and disabled states. Scrollbars across every window and popup use theme-aware CSS tracks and thumbs on Windows and Linux, retaining browser scrolling and leaving macOS scrolling unchanged.
- `internal/i18n`: the language Go uses for menus, window titles, dialogs, progress and errors. English is the source: `i18n.Errorf` and `i18n.T` take the English format string, and Simplified (mainland) and Traditional (Taiwan) Chinese catalogs map it to its translation, so the internal packages keep readable English in code and tests. Errors are translated when their text is read, which is when Wails hands them to the frontend. The system's preferred languages come from `defaults read` on macOS, `GetUserPreferredUILanguages` on Windows and the POSIX locale variables elsewhere, read once at launch. A test parses the Go source and fails on any translatable string missing from either catalog or with different formatting verbs. The frontend draws everything else from typed dictionaries in `frontend/src/locales`, using the locale Go reports with the settings; tests keep the three dictionaries the same shape and catch Taiwan wording in the mainland dictionary or Simplified characters in the Taiwan one. The application menu has no Help menu: the only item Wails provides there navigates the editor window to wails.io. The subtitle font is a settings value Go validates (no characters that would need escaping in CSS); each window applies it as the `--subtitle-font` CSS variable.
