# Architecture

The application follows the official Wails v3 React template: `main.go` embeds Vite assets and registers `EditorService`; generated interfaces and callable bindings live under `frontend/bindings`. The backend owns file dialogs, project state, credentials, external commands, and uploads. There is no database, authentication system, or cloud storage.

- `internal/subtitle`: strict UTF-8 SRT cue/timestamp parsing, validation, and export. Imported identifier numbers remain strings; internal cue IDs are separate so duplicate SRT identifiers do not collapse rows.
- `internal/project`: immutable imported cues plus editable state; bounded snapshot-based undo/redo survives JSON reopening. Speaker metadata stays separate from SRT text. Accepting/rejecting a proposal is itself a history operation.
- `internal/analysis`: transcription provider interface and OpenAI multipart implementation. Range-relative timestamps are translated to media timestamps. Alignment uses positive temporal intersections and retains all overlapping speakers; cross-boundary segments are marked for review rather than split into invented words. Correction suggestions are the actual audio transcript, with no extra stylistic rewrite call.
- `internal/media`: FFmpeg extraction, local waveform peaks (decoded audio is streamed through memory, never written or uploaded), dependency checks, exclusive output creation, and optional yt-dlp integration. Commands use argument arrays, never shell concatenation. YouTube URLs are normalized to single video IDs, user yt-dlp configuration is ignored, and playlists are rejected.
- `service.go`: serializes state updates with a mutex, returns detached snapshots, rejects edits during long processing, and shares a cancellable context across subprocesses and HTTP. Temporaries are removed. Waveform decoding runs outside that busy state with its own context: a newer request cancels an older one, and shutdown cancels both. Audio is exposed to the player through an HTTP Range-capable route that serves only the selected local file, with no arbitrary path parameter.
- `frontend/src`: an editor-style window (toolbar, cue grid, viewer, tabbed inspector, canvas waveform timeline that renders only the visible range, status bar), selection/playback synchronization, explicit field application, character-level Traditional Chinese diff highlights, individual suggestion decisions, speaker identity management, and theme selection. The same bundle also renders the settings and welcome windows, chosen by a `?window=` query. Outside macOS, Go opens every window frameless and adds `chrome=custom` to its URL; the frontend then draws minimise/maximise/close buttons at the right of the title bar (`WindowControls.tsx`) through the Wails window runtime, where the macOS inset title bar leaves room for the traffic lights on the left. The API key crosses the frontend boundary in one direction only: typed into those windows and handed to Go for the credential store. Go returns just its source (`env`, `keychain` or none).

Labels from different diarization requests are namespaced per run because OpenAI's “A” is not a persistent identity. Users can rename identities and manually assign cues to a shared identity. This avoids falsely identifying people across requests. A future provider can add voice-reference support without conflating original cues, edited cues, segments, identities, and suggestions.

A complete snapshot per operation is intentionally simple for v0.1. With 100 history entries this is suited to moderate subtitle files; long episodes should use a compact command/delta history later. Persistence uses new files rather than in-place writes to protect source material. Explicit approval before upload is part of the editor flow, independently of authorization to download audio.
- `internal/settings`, `internal/keychain`, `internal/update`: preferences as one atomically replaced JSON file, the OpenAI key in the system credential store (macOS keychain through `/usr/bin/security` and Linux Secret Service through `secret-tool`, the key passed on stdin and never as an argument; Windows Credential Manager through the `advapi32` credential API), and a read-only GitHub release lookup with semantic-version ordering. `internal/media` resolves FFmpeg and yt-dlp from a configured location, `PATH`, or (outside Windows) the Homebrew folders and `/usr/local/bin`. None of them depend on Wails; `settings_service.go` exposes them and owns the three windows and the macOS menu; Windows and Linux have no application menu.
