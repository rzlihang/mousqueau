> Repository copy of the Mousqueau design system (https://claude.ai/artifact/KhcjCAggS16469ag6zeMsE), extracted from `frontend/src/style.css`, `frontend/src/App.tsx` and the antd 5.29.3 theme. `components/lib/` is not checked in: React 18.3.1, ReactDOM, dayjs and antd come from `frontend/node_modules`. `tokens.css` is generated by the artifact page from `tokens.json`. The contrast fixes described under Color exist only in this design system; the app still ships antd's defaults. The component previews were checked in headless Chromium on Linux, light and dark; nothing here was checked in the macOS WebView.

Mousqueau is a desktop subtitle editor: it corrects existing SRT subtitles against the audio and reviews who is speaking. The interface is a calm, dense work surface built on Ant Design 5 with one blue accent. It shows its work, keeps the original visible, and asks before anything leaves the machine.

## Building with it

- Load React 18, ReactDOM 18, dayjs and antd 5.29 (all in `components/lib/`), then `tokens.css`, `components/bundle.css` and `components/bundle.js`. Wrap the screen in `Mousqueau.Provider`.
- Use antd components for every control (Button, Tag, Alert, Input, Select, Checkbox, Switch, Modal, Empty, Spin, message). Never restyle them by hand: the look comes from the `Provider` theme (`colorPrimary` = `primary`, `borderRadius` 6, plus the contrast fixes under Color) and antd's default and dark algorithms.
- Use the Mousqueau components (`AppHeader`, `StatusBar`, `Panel`, `CueCard`, `CueEditor`, `SpeakerManager`, `SuggestionCard`, `DiffText`, `Timecode`) and the `bundle.css` classes for the app's own surfaces.
- Write custom CSS only with tokens: `var(--panel)`, `var(--space-12)`, `var(--radius-md)`.

## Content

**Language.** Interface copy is Simplified Chinese (导入媒体, 保存说话人, 校正建议). Subtitle content keeps its own script: the demo conversation is Traditional Chinese (我們今天要討論新的字幕編集器。) and is never converted. Product and format names stay in their own spelling: SRT, JSON, FFmpeg, OpenAI, YouTube, yt-dlp, API, `OPENAI_API_KEY`. An unassigned speaker is `Unknown`, in English.

**Voice.** Plain, procedural, and specific about consequences. Say what will happen, what will not, and where data goes.

- Buttons are a verb and its object: 导入 SRT, 套用编辑, 下载并导入所选字幕, 另行下载音频到本机并载入.
- Any action that sends data off the machine says so in its label: 上传所选音频并分析, then 确认上传并分析 in the confirmation.
- State limits next to the control: 每次 1–5 分钟。请自行确认选取范围与音频内容。
- Reassure with facts, not adjectives: 文件保留在本机。仅确认分析时上传选定音频。 / 下载不会自动上传到 OpenAI。开始分析仍需另行确认。
- Errors say what is wrong and the valid form: 请输入 HH:MM:SS,mmm，分与秒须为 00–59。 / 请选择 60–300 秒的范围。
- Empty states name the next step: 导入 SRT 或载入示例开始编辑.

**Punctuation.** Full-width Chinese punctuation in sentences (。，：；（）？) and the full-width slash in alternatives (多人、重叠或跨句／范围边界). Use `·` between parts of one status (OpenAI 未配置 · 可离线编辑, #3 · 00:00:07,000), `→` for a time range inside a cue, `—` between range ends in prose, an en dash for numeric ranges (60–300), `…` for work in progress (处理中…), and a trailing ` •` on 保存项目 for unsaved changes. No exclamation marks and no emoji.

**Times.** Show subtitle times as SRT time, `HH:MM:SS,mmm`, in the mono family. Analysis ranges alone are whole seconds, with the unit in the label: 开始（秒）.

## Visual foundations

**Color.** The palette is cool neutrals with one blue.

- Ground: `bg` behind everything; `panel` for the header, panels and cards; `select` for the hovered or selected cue. Text is `ink`; secondary text is `muted`.
- Edges: 1px `line` hairlines. Panels and cards are separated by borders and the `bg` gaps between them, never by shadows.
- Accent: `primary` fills exactly one main button per area. `cue-accent` marks the selected cue's border and the playing cue's inset bar.
- Meaning: status tags use antd presets with a fixed meaning each: `tag-green-*` ready, `tag-orange-*` needs attention or review, `tag-gold-*` unapplied change, `tag-blue-*` pending decision, default for off or unknown. `danger` is only for cancelling running work.
- Speakers: `speaker-1` to `speaker-3`, assigned in order and cycling; `speaker-4` exists only in the analysis palette. Always print the speaker's name on the tag.
- Diff: `diff-removed` with line-through for removed characters, `diff-added` at weight 600 for added ones.
- Video sits on `video-ground` in both themes.

Contrast: `ink` and `muted` pass 4.5:1 on `bg`, `panel` and `select` in both themes (light `muted` on `bg` only just, at 4.51:1). This system raises four colors above antd's defaults so text reaches 4.5:1: the light `tag-green-text`, `tag-orange-text` and `tag-gold-text` (antd's step 8 or darker instead of step 7), and `danger` in both themes. `Provider` applies these through the antd theme. The app itself still ships antd's defaults, so do not copy these values back as "what the app looks like". Still below 4.5:1 and kept from the source: white on `speaker-2` (2.3:1), `speaker-3` (3.6:1) and `speaker-1` (4.1:1), and `cue-accent` on dark `panel` (3.0:1, a border). Never let one of these colors carry meaning alone.

**Type.** System fonts only; nothing is downloaded. App surfaces use `sans` (system-ui, then Noto Sans TC for Chinese); antd controls use antd's own `antd` stack; times and cue metadata use `mono`.

- `brand` once, for the product name. `panel-title` for each panel's h2; `section-title` for the editor heading.
- Subtitle text in `cue-text` (14/1.6); comparison text in `comparison` (13/1.7); helper text in `caption` (12/1.6, `muted`).
- `clock` for the playhead, `cue-meta` for the cue's identifier and time range, `time-field` for time inputs.
- Controls: `control` (14/22) and `control-sm` (12/20) come from antd.

**Spacing and layout.** The source uses exact pixel steps, not a grid: keep them. `space-18` panel padding and window gutter, `space-14` between panels, `space-12` inside cards, `space-8` between cards and small items. The window is header, status bar, then the three-column workspace (media, cues, review) filling the remaining height; see `Provider` for the column rules and breakpoints (`bp-two-column`, `bp-one-column`).

**Shape.** `radius-panel` (10px) for panels, `radius-suggestion` (7px) for suggestion cards, `radius-md` (6px) for cue cards, media and controls, `radius-lg` for alerts and modals, `radius-sm` for tags.

**Elevation.** Flat. The only shadows are `shadow-playing`, the inset bar on the playing cue, and antd's `shadow-overlay` on modals and dropdowns.

**States.** Hover and selected cues fill with `select` and take a `cue-accent` border. Busy work disables controls rather than hiding them and shows a small Spin with the phase and a 取消处理 button. Unapplied edits show a gold 尚未套用 tag and lock suggestion decisions. Decided suggestions fade to `opacity-settled`. Focus rings are antd's defaults; cue cards rely on the browser's default focus outline.

**Motion.** antd's default transitions only, plus smooth scrolling to bring the selected cue into view. No decorative animation.

**Imagery.** None. The only illustration is antd's `Empty` graphic in empty states.

## Iconography

Mousqueau uses no icon set. Every action is a text button, and status is a word in a tag. The only glyphs on screen are antd's built-in ones (select arrow, checkbox tick, the confirm dialog's warning icon, the Empty illustration) and the punctuation marks above (`→`, `·`, `•`). Do not add icons or emoji.

## Logo

The app mark is `assets/Logos/mousqueau-mark.svg`, the window favicon: a 32px square in `primary` (#2867c7) with `radius-md` corners and a white "M". Its letter is set in the viewer's default font, so it renders differently across systems. In text and headers, set the name as a word in `brand`: Mousqueau. The macOS, Windows and Linux app icons are still the Wails template's and are not Mousqueau's mark; do not use them.
